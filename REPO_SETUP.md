grow the repo without limit and never compress. **Rule of thumb: if you'd have to re-type
it after a reinstall it's code; if it changes when you press a button it's data.**

## 2. Yes — you can store this on GitHub and run it locally

That's exactly what git is for. Three things to get right first.

### ⚠️ (a) Don't put the git clone inside OneDrive

Your folder today is `C:\Users\megha\OneDrive\Documents\Reading`. OneDrive syncs the hidden
`.git` folder file-by-file in the background, which reliably corrupts repositories —
phantom `.lock` files, "index is corrupt" errors, and `.git` objects turning into
"conflicted copy" duplicates. OneDrive and git both want to be the thing syncing that
folder, and they fight.

**Split them:**

```
C:\Users\megha\book-tools\                     <- git clone (code)   — synced by GitHub
C:\Users\megha\OneDrive\Documents\Reading\     <- data               — synced by OneDrive
C:\Users\megha\OneDrive\Pictures\...\Books\    <- screenshots        — synced by OneDrive
```

This works with almost no code changes, because the scripts already point at the data with
absolute paths (`EXCEL_PATH = Path(r"C:\Users\megha\OneDrive\Documents\Reading\books_output.xlsx")`).
The `.py` files find each other via `SCRIPT_DIR`, so they can all move together. Each half
keeps syncing through the tool that's actually good at it, and you get real version history
and rollback on the code.

### ⚠️ (b) One bug this split will expose

`storygraph_to_read.py` line 26 loads the config from **next to the spreadsheet**:

```python
_config_path = EXCEL_PATH.parent / "launcher_config.json"   # -> ...\Reading\
```

but `book_launcher.py` **writes** it to **next to the scripts** (`SCRIPT_DIR`). Today those
are the same folder so it works by accident. Once you move the code out of `Reading`, the
Settings you save in the GUI will silently stop reaching the StoryGraph script.

Fix: point both at the same place. Easiest is to make `storygraph_to_read.py` read the
config from its own directory:

```python
_config_path = Path(__file__).parent / "launcher_config.json"
```

Say the word and I'll make that change.

### ⚠️ (c) The hardcoded username

Every data path contains `C:\Users\megha\`. Syncing to a second PC with a different Windows
username means every path breaks. If you only ever use machines logged in as `megha`,
you're fine. Otherwise the paths should move into `launcher_config.json` — a bigger change,
worth doing only if you actually need it.

## Data files: already untracked

All seven have been removed from git tracking with `git rm --cached`, which touches only the
git index — **your actual files are untouched on disk.** When you pull this branch into your
Reading folder, the spreadsheets, logs, and your `launcher_config.json` all stay exactly
where they are; git just stops carrying them.

The `.gitignore` covers them plus future logs, screenshots, and decision exports, so they
can't creep back in.

### One thing to know

`apply_reading_log.py` does **not** create `books_output.xlsx` or `my-reading-log.xlsx` if
they're missing — it prints `WARN: ... not found` and skips that half of the update
(lines 124 and 222). So on a new machine, wait for OneDrive to finish syncing your Reading
folder before running anything. A fresh `git clone` on its own won't give you those files,
by design.

> **Note:** this stops *future* commits from carrying these files, but the old versions stay
> in git history — the repo won't shrink. Since no real API key was ever committed
> (`openai_api_key` is `""` in the version that was pushed), that's harmless: the history
> just holds some stale spreadsheets. If you ever do push a real key, rotate it at
> platform.openai.com rather than trying to scrub history.

## Setting up on a computer

```powershell
# 1. Clone OUTSIDE OneDrive
cd C:\Users\megha
git clone https://github.com/meghanareed/book-processing.git book-tools
cd book-tools

# 2. Install dependencies (one step instead of per-button)
py -m pip install -r requirements.txt
py -m playwright install chromium

# 3. Create your local config and add your OpenAI key
copy launcher_config.example.json launcher_config.json
notepad launcher_config.json

# 4. Run
.\Launcher.bat
```

The data folders keep syncing through OneDrive, so `books_output.xlsx` and your screenshots
are already there.
